# Partner Agent для ЦФТ и ШИФТ

Отдельный модуль команды для хакатона НЭТИ НЕКСТ. Внутри находятся React-интерфейс и Python-сервис регистрации и входа. Чат обращается к основному бэкенду команды по присланному контракту SSE.

| Компонент | Порт | Назначение |
| --- | --- | --- |
| Фронтенд Vite | 5173 | Разработка интерфейса |
| Основной бэкенд команды | 8000 | Прокси к RAG, сохранение диалогов, авторизация запросов |
| RAG команды | 8001 | Поиск и генерация ответов |
| Этот сервис авторизации | 8002 | Аккаунты и серверные сессии |
| Фронтенд в Docker | 8080 | Nginx, интерфейс и прокси API |

## Запуск в Windows

Потребуются Python 3.12 и Node.js 22.12+ либо 24 LTS. Откройте корневую папку модуля в редакторе.

Первый терминал PowerShell

```powershell
cd auth_service
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8002
```

Второй терминал из корневой папки модуля

```powershell
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173. Регистрация и вход работают сразу. Для ответов в чате основной бэкенд команды должен слушать порт 8000. Пока он недоступен, интерфейс показывает ошибку с возможностью повторить запрос.

Swagger сервиса авторизации находится по адресу http://127.0.0.1:8002/docs. POST-запросам нужен заголовок `X-Requested-With: PartnerAgent`. Тестировать их удобно через фронтенд или HTTP-клиент с этим заголовком.

## Запуск в Linux и macOS

```bash
cd auth_service
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8002
```

Команды фронтенда совпадают с Windows. Если бэкенд расположен на другом адресе, скопируйте `frontend/.env.example` в `frontend/.env`, измените `AGENT_PROXY_TARGET` и перезапустите Vite. Для браузера API по умолчанию остаётся на том же origin благодаря прокси.

## Запуск через Docker

```bash
docker compose up --build
```

Интерфейс будет доступен по адресу http://localhost:8080. Сервис авторизации доступен другим контейнерам как `http://auth:8002`. Основной бэкенд по умолчанию ожидается на хосте по порту 8000. Для подключения из контейнера он должен слушать `0.0.0.0`. Другой адрес задаётся переменной `AGENT_UPSTREAM` в корневом `.env` по образцу `.env.example`.

SQLite хранится в Docker-томе `auth_data`. `docker compose down` сохраняет аккаунты. `docker compose down -v` удаляет этот том вместе с аккаунтами.

## Контракт для основного бэкенда

Фронт отправляет POST `/api/v1/ask/stream` на основной бэкенд. Формат тела соответствует сообщению напарника.

```json
{
  "question": "Какие технологии используют в ЦФТ?",
  "history": [
    {"role": "user", "content": "Чем занимается компания?"},
    {"role": "assistant", "content": "Предыдущий завершённый ответ"}
  ]
}
```

Текущий вопрос передаётся отдельно от истории. В историю входят завершённые пары сообщений активного диалога. Оборванный или ошибочный ответ исключается. Новый диалог отправляется с пустой историей. Отмена запроса закрывает поток в браузере, основной бэкенд должен передавать отмену дальше RAG.

Ожидается `Content-Type: text/event-stream` и последовательность событий

```text
event: sources
data: [{"doc_id":"abc123","source":"reglament.pdf","page":4,"score":0.78}]

event: token
data: {"text":"Начало ответа "}

event: token
data: {"text":"и продолжение."}

event: done
data: {}

```

Поддерживаются UTF-8, LF/CRLF, произвольное разбиение сетевых пакетов и SSE-комментарии. Завершение соединения до `done` считается прерыванием. Дополнительно распознаётся `event: error`. Полный ответ ограничен тайм-аутом 120 секунд.

Для открываемых источников добавьте в элемент `sources` необязательное поле `url` с HTTP(S)-адресом страницы или вашим маршрутом скачивания. Пока источник содержит только имя файла, фронт показывает его имя и страницу. Значения `score` не выдаются пользователю как вероятность правильности ответа.

```json
{"doc_id":"abc123","source":"Описание продукта","page":4,"url":"https://www.cft.ru/"}
```

Пример URL выше демонстрирует формат. Бэкенд должен вернуть адрес конкретного материала, подтверждающего ответ.

## Авторизация и проверка пользователя

| Метод | Маршрут | Тело | Результат |
| --- | --- | --- | --- |
| POST | `/api/v1/auth/register` | `name`, `email`, `password` | 201, сессия и cookie |
| POST | `/api/v1/auth/login` | `email`, `password` | 200, сессия и cookie |
| GET | `/api/v1/auth/me` | Cookie | 200, текущая сессия, либо 401 |
| POST | `/api/v1/auth/logout` | Cookie и `X-CSRF-Token` | 204, отзыв сессии |
| GET | `/health` | — | Проверка доступности БД |

Регистрация автоматически выполняет вход. Пароль содержит от 8 до 128 символов. Email используется как логин, его владение в этом модуле не подтверждается. Проверка почты и восстановление пароля потребуют подключения почтового сервиса.

Ответ входа, регистрации и `me`

```json
{
  "user": {"id":"uuid","name":"Вова","email":"vova@example.com"},
  "csrf_token":"случайная строка",
  "expires_at":"2026-11-28T12:00:00+00:00"
}
```

Идентификатор сессии передаётся в HttpOnly-cookie `partner_session`. Его значение отсутствует в JSON. Сессия действует 7 дней, хранится в БД и отзывается при выходе. Новый вход заменяет предыдущую сессию этого браузера. Пароли хешируются Argon2id, в БД сохраняется SHA-256 от случайного идентификатора сессии. Ограничение попыток входа и регистрации хранится в БД и переживает перезапуск.

Основной бэкенд должен проверять пользователя на каждом защищённом маршруте. Пример зависимости FastAPI для сервиса на порту 8000

```python
import hmac
import os

import httpx
from fastapi import HTTPException, Request

AUTH_URL = os.getenv("AUTH_URL", "http://127.0.0.1:8002")

async def current_user(request: Request):
    try:
        async with httpx.AsyncClient(timeout=5) as client:
            response = await client.get(
                f"{AUTH_URL}/api/v1/auth/me",
                headers={"Cookie": request.headers.get("cookie", "")},
            )
    except httpx.RequestError:
        raise HTTPException(503, "Сервис авторизации недоступен")
    if response.status_code == 401:
        raise HTTPException(401, "Войдите в аккаунт")
    if response.status_code != 200:
        raise HTTPException(503, "Не удалось проверить сессию")
    session = response.json()
    if request.method not in {"GET", "HEAD", "OPTIONS"}:
        provided = request.headers.get("x-csrf-token", "")
        if not provided or not hmac.compare_digest(provided.encode(), session["csrf_token"].encode()):
            raise HTTPException(403, "Не удалось проверить запрос")
    return session["user"]
```

Подключите зависимость через `Depends(current_user)` к `/api/v1/ask`, `/api/v1/ask/stream` и маршрутам истории. `user_id` берётся из результата проверки. Переданный пользователем текст или произвольное поле JSON не задаёт владельца диалога. Поток и загрузку документов проксирует основной бэкенд. Права на административные маршруты документов он проверяет отдельно.

В Docker-конфигурации Nginx дополнительно проверяет сессию перед `/api/v1/`. Для локального Vite-прокси проверка пользователя остаётся обязанностью основного бэкенда. RAG-порт 8001 предназначен для внутреннего обращения основного бэкенда.

## База и история

Без настроек сервис создаёт SQLite в `auth_service/data/auth.db`. Чтобы использовать вашу PostgreSQL, задайте перед запуском

```text
DATABASE_URL=postgresql+psycopg://user:password@host:5432/partner_auth
```

Таблицы `auth_users`, `auth_sessions`, `auth_rate_limits` создаются при запуске. Для уже существующего проекта согласуйте управление схемой с командой. Автоматических миграций старой чужой схемы модуль не выполняет.

Диалоги интерфейса пока хранятся в `sessionStorage`, отдельно по `user.id`. Они сохраняются при обновлении страницы в той же вкладке и очищаются при выходе. Секрет сессии там не хранится. По присланному контракту основной бэкенд может сохранять вопросы и склеенные токены в свою БД. Серверное получение списка и содержимого диалогов нужно подключить после согласования этих маршрутов.

## Настройки для HTTPS

В публичном окружении задайте `COOKIE_SECURE=true`, укажите точный HTTPS-origin фронтенда в `ALLOWED_ORIGINS` и используйте HTTPS на входном прокси. В локальных примерах HTTP оставлен для разработки. Для вынесенного API фронт использует `credentials: include`, а сервис разрешает CORS только для перечисленных origin.

API-ключи моделей относятся к RAG или основному бэкенду. В переменные `VITE_*` попадают только публичные адреса API, содержимое этих переменных входит в JS-сборку браузера.

## Проверки

```bash
cd frontend
npm test
npm run build
```

Из `auth_service` после установки зависимостей

```bash
python -m unittest discover -s tests -v
```

Тесты авторизации покрывают хеширование, cookie, повторную и конкурентную регистрацию, неверный пароль, поддельную и истёкшую сессию, ротацию при входе, CSRF, выход, перезапуск и ограничение попыток. Тесты фронта проверяют SSE на побайтовом UTF-8, CRLF, обрыв потока, состав истории и допустимые ссылки.

При подготовке модуля прошли 7 тестов авторизации на SQLite, 5 тестов фронтенда и production-сборка. Интерфейс проверен в браузере на настольной ширине и в области шириной 390 пикселей. Поток, ссылки, повтор, остановка и независимость новых диалогов проверены с временным тестовым API по предоставленному контракту. Подключение к реальному RAG, запуск Docker и режим PostgreSQL предстоит проверить в окружении команды.

## Добавление в GitHub команды

Скопируйте папки `frontend`, `auth_service`, `deploy`, `compose.yaml`, `.gitignore` и `.dockerignore` в согласованное место вашего репозитория. Сохраните `package-lock.json` и закреплённые Python-зависимости. Настройки из `.env.example` можно объединить с настройками команды. Каталоги `.venv`, `node_modules`, локальная БД и настоящий `.env` в репозиторий не добавляются.
