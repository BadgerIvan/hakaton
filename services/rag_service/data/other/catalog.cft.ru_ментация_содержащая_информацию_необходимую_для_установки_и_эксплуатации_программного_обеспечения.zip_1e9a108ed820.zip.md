1. Архитектура
Система “ЦФТ Веб-навигатор”(Реестровая запись №21303 от 08.02.2024) является
универсальным рабочим местом пользователя, которое позволяет просматривать
Экземпляры Типов Базовых Понятий (ТБП), выполнять операции и навигацию в рамках
информационной модели “ЦФТ – Платформа развития” в соответствии с правами доступа по
средствам взаимодействия с Яндекс браузером(Реестровая запись №3722 от 23.07.2017) или
любым другим современным, поддерживающим ES5 стандарт (IE8 и более ранние версии не
поддерживаются).
“ЦФТ Веб-навигатор”, разработан на JavaScript-фреймворке Vue2 и публикуется для рабочих
мест в виде скомпилированной статики(css, js, html, png, json) через веб-сервер nginx,
упакованный в Docker контейнер.
Бэкендом является Сервер Приложений(2MCA, 2MCA-PROXY или 2MCA DBI) от продуктов
созданных на базе “ЦФТ - Платформа развития”.
Прямого взаимодействия с БД не предусматривается, поэтому неважно какая СУБД будет
стоять за СП.
2. Требования к АПК
2.1. Продукты на базе ЦФТ – Платформа развития
Продукт созданный на базе “ЦФТ - Платформа развития” к которому будет производиться
подключение, должен быть запущен в любом режиме позволяющим обслуживать
взаимодействие по протоколам http(s), т.е.: 2MCA, 2MCA-PROXY или 2MCA DBI с версией не ниже
2.62.12 или 3.8.14 для DBI.
Допускается использование любой версии ЦФТ-Банк или других продуктов с ТЯ версии
совместимой с минимальной версии СП требуемой для ЦФТ Веб-навигатор.
В случае промышленного развертывания, сервер приложения обязательно
должен быть дополнительно сконфигурирован для возможности
 обслуживания прямого трафика от браузера, см подготовка сервера
приложений.

4.1. Подготовка сервера приложений
Для прямого взаимодействия браузера и сервера приложений, а также возможности
использовать методы аутентификации NTLM и OpenID Connect, необходимо:
1. Обеспечить отношение URL сервера приложений с URL ЦФТ-Веб-Навигатора по
правилам SameSite. В данной истории требование к совпадению домена второго уровня
врятли станет проблемой, а вот разворачиванием сервера приложений по https
протоколу, особенно в тестовых средах мало кто занимался.

браузере.
2. Обеспечить наличие библиотеки webnav-lib в составе war, наряду со всеми остальными
библиотеками WEB-INF\lib\:
◦Если это готовый war с 2MCA-PROXY, то можно через 7z положить
◦Если это локальный СП, то необходимо прописать дополнительную зависимость в
pom.xml
◦Если это 2MCA или 2MCA DBI собираемый по pom.xml, который публикуется вместе с
очередной версией ЦФТ-Банк, то ничего не нужно делать, она там уже будет
присутствовать

①можно настраивать ссылку на СП в виде строки или массива. Если настраивать массив,
то второй параметр отвечает за установку флага "Автоматический вход"
данный конфигурационный файл необходимо рассматривать как ini файл с
предварительно настроенными адресами серверов приложений, в случае
если пользователю нужно будет подключиться к какому-то другому серверу, 
он должен будет указать его URL на странице авторизации, аналогично
классическому навигатору.
Также в текущем JSON файле можно прописать еще настройку регулирующую механизм
получения имени пользователя операционной системы, т.е. есть пользователь системы на
базе ЦФТ-Банк, он может быть технический, а есть реальный человек и не на продуктивных
стендах они могут отличаться. Эта информация попадает в журналы регистрации
пользователей. Есть 2 варианта настройки:
1. Можно на форму входа добавить еще одно поле ФИО в котором просить пользователя
собственноручно ввести свои идентификационные реквизиты(getUsernameMode=login-
form)
2. Можно получить имя профиля через веб сервис с Kerberos или OAuth авторизацией
возвращающей json(getUsernameMode=json). В данном режиме добавляются еще такие
параметры как URL(getUsernameURL), по которому будет произведен запрос и имя
поля(getUsernameField) в JSON из которого забирать имя.
Если ни один из вариантов не подходит или не будет настроен, в журнале
 авторизации на месте отвечающем за пользователя ОС будет пустота.
Пример(webapp-config.json):
{
"schemas": {
"DEV": "http://dev-wls.bank.ru:8001/ibso",
"PROD": ["https://sp.bank.ru/ibso", true]
},
"auth": {
"getUsernameMode": "json", ①
"getUsernameURL": "/env", ②
"getUsernameField": "username"

2.3 Суммирование по колонкам
Команда выполняет суммирование значений по выделенным колонкам. Результат
выдается в отдельном окне.
Для того, чтобы просуммировать значения в колонке, следует выделить ее
(щелкнув левой кнопкой мыши по заголовку, удерживая нажатой клавишу Ctrl, или
установив курсор в ячейке колонки), а затем вызвать процедуру суммирования.
Если тип колонки поддерживает статистику, то в результате выполнения операции
будут представлены два числа – сумма значений записей в колонке и общее количество
просуммированных записей.
Если тип колонки не поддерживает статистику, в результате выполнения операции
в первом столбце будет содержаться информация обо всех возможных значениях
колонки, а во втором столбце будет указано количество записей, просуммированных в
первом столбце.
Для того, чтобы просуммировать значения в нескольких колонках следует
выделить их и вызвать процедуру суммирования (о выделении нескольких колонок
одновременно см. пункт (3.6 Выделение ячеек, столбцов в представлении 56 ). Если
операцию суммирования поддерживают все типы указанных колонок, то будет
подсчитана сумма для каждой колонки в отдельности, и указано количество записей, по
которым проводилось суммирование.
Если среди указанных колонок будет присутствовать хотя бы один тип, не
поддерживающий статистику, будет проведено суммирование по каждому уникальному
значению несуммируемых колонок в отдельности.

3.3 Форма представления
Выбор представления определяет перечень и форму визуализации списка
экземпляров ТБП.
Ширина колонок, способ выравнивания значений в колонках и форма отражения
значения конкретного реквизита в списке описывается при формировании
представления.
По умолчанию форма представления определяется типом реквизита:
Простой (число) - формат представления числа определяется параметрами этого
типа данных "Размер" и "Точность" (параметры указываются при создании
соответствующего типа администратором). При этом "Размер" определяет общее
количество знаков вместе с десятичной точкой, а "Точность" – количество знаков после
запятой.
Простой (дата) - дата в формате ДД/ММ/ГГГГ.
Простой (логика) - реквизит может иметь значения "Да" или "Нет", либо быть
неопределенным, в таком случае на экран выводится значение: "Пусто".
Простой (строка) - значение ячейки содержит строку, без каких-либо
дополнительных символов.
Простой (мемо) - вывод текста ограничен шириной колонки. По двойному щелчку
левой кнопкой мыши выводится информационное окно, содержащее полное значение
мемо-поля.
Элементы структуры - все элементы структуры отображаются по правилам
визуализации реквизитов соответствующего типа.
Неразыменованная ссылка на экземпляр ТБП (в том числе в справочник) -
значение (***), если ссылка не пустая, в противном случае – ячейка представления не
будет содержать ничего. По двойному щелчку левой кнопкой мыши происходит переход в
режим работы с экземплярами ТБП, являющимися значениями ссылки.
Элементы разыменованной ссылки на экземпляр ТБП (в том числе в
справочник) - все элементы разыменованных ссылок отображаются по правилам
визуализации реквизитов того ТБП, на экземпляр которого ссылается реквизит текущего
экземпляра. По двойному щелчку на этом поле происходит переход к просмотру
реквизитов соответствующего экземпляра ТБП.

ее), а затем выделять другие строки, при этом удерживая нажатыми кнопки Shift или

клавише Shift будут выделены все строки между первой и последней из выделенных.
Выделение экземпляров влияет на запуск операций. При этом следует иметь в
виду, что порядок вызова операций для выделенных экземпляров совпадает с порядком их
выделения.
При наложении фильтра на представление часть выделенных экземпляров может
не удовлетворить условиям фильтра – в этом случае такие экземпляры теряют
